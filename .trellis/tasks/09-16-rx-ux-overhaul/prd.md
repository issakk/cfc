# 接收可靠性与操作体验重构（收件箱 + 模式选择 + CI 构建）

## Goal

修掉互相纠缠的三个接收 bug（保存弹窗打断解码 / 一帧多文件丢掉 / 取消保存泄漏临时文件），补齐操作缺口（可见的发送端入口、能看懂的模式选择、完成反馈与收件箱），并新增 GitHub Actions 构建（本地不编译，功能写全后一次性 push）。

## 背景

cfc 是 Android 端 cimbar 光通信接收器（v0.6.8，仅 arm64-v8a，minSdk 21 / targetSdk 36）。现状是「仅仅能用」的 demo：

- 每收完一个文件就弹 `ACTION_CREATE_DOCUMENT` → Activity `onPause` → `shutdownJNI()` 把解码器整条销毁 → 回来后 fountain 状态与进度归零，多文件接收退化成「收一个重来一次」。
- `jni.cpp` 用单个字符串回传结果，同一帧完成多个文件时只把最后一个报给 Java，其余被 `_completed` 标记后永久静默。
- 取消保存时 `finally` 不执行，临时文件永久留在 `filesDir`。
- 交互只有隐藏手势（任意位置垂直滑动进入发送端）和一个 48dp、语义不明、会自己翻转的模式开关；无完成反馈、无已收文件列表、无相机控制。

## Requirements

- R1 **默认保存位置**：接收完成的文件自动发布到系统下载目录 `Downloads/CameraFileCopy/`。API 29+ 走 MediaStore（无需任何权限），API 21–28 回退公共外部存储目录（含权限声明与运行时请求）。
- R2 **不打断解码**：进入后台、弹窗、打开其他 Activity 不再销毁解码器；仅 Activity 真正销毁时释放。
- R3 **一帧多文件**：JNI 一次返回该帧全部新完成文件，全部进入发布队列，一个都不丢。
- R4 **临时文件生命周期**：发布成功即删除；发布失败保留并在收件箱标记「未保存」可重试；启动时清理无主临时文件。
- R5 **可见的发送端入口**：屏幕上有明确的按钮进入编码端页面，返回也有可见按钮；保留垂直滑动作为快捷方式。
- R6 **模式选择**：改为带文字说明的选择器（自动 / B / Bm / Bu / 4C，含适用场景），当前模式以文字呈现；用户选择跨启动保留；自动识别到模式只更新提示，不改变用户选项。
- R7 **状态与反馈**：界面显示状态（等待 / 检测到码流 / 接收中 xx% / 完成）与已收文件数；每个文件完成时震动 + 短提示音。
- R8 **收件箱**：可查看接收记录（文件名、大小、时间、保存位置 / 未保存状态），可打开、分享、另存为。
- R9 **CI**：push 到 GitHub 后自动构建 debug APK 并上传产物；构建需处理 NDK `29.0.14206865`、OpenCV `4.12.0` Android SDK、`cimbar-js-bits` 子模块、JDK 17，并覆盖 `gradle.properties` 里硬编码的本机路径。

## Acceptance Criteria

- [ ] AC1 连续接收多个文件：无系统保存对话框打断预览；进度不回退；每个文件都出现在 `Downloads/CameraFileCopy/` 与收件箱。
- [ ] AC2 收到文件后切到别的界面再回来，解码器进度不重置（不重新扫描）。
- [ ] AC3 写入失败（无空间/无权限）时文件不丢：留在收件箱标记「未保存」且可重试，不崩溃。
- [ ] AC4 取消/退出不产生「没人知道」的孤儿文件：发布失败的残留会在收件箱里以「未保存」呈现并可重试，重启后由收件箱接管；`filesDir` 里只可能剩下正在接收的临时文件或已登记的未保存文件。
- [ ] AC5 冷启动 3 秒内可见：发送端入口按钮、模式入口按钮、状态文字。
- [ ] AC6 不看代码的人能靠对话框文字选出正确模式；选择重启后仍在。
- [ ] AC7 自动识别到模式时出现提示文字，且用户选中的选项不变。
- [ ] AC8 每个文件完成有震动 + 提示音；静音/勿扰下不崩溃。
- [ ] AC9 收件箱条目可点开（打开文件），可分享。
- [ ] AC10 push 后 GitHub Actions 构建成功并产出 APK artifact；构建不依赖本机路径。
- [ ] AC11 竖屏启动，预览与解码正常；预览尺寸仍落在短边 960–1080 的分辨率档（竖屏下应选中 1920×1080 一类，而不是退化到 1024×768）。
- [ ] AC12 产物 `applicationId` 为 `com.github.issakk.cfc`，可与旧包名并存安装；JNI 正常加载（无 `UnsatisfiedLinkError`）。

## 追加需求（第二轮）

- R10 **竖屏**：`MainActivity` 与 `WebViewActivity` 从横屏锁定改为竖屏锁定；切换方向后解码输入分辨率不得退档。
- R11 **包名改为 `com.github.issakk.cfc`**：`namespace` / `applicationId` / Java 包与目录 / JNI 符号 / 布局里自定义 View 的全限定名同步更新；`AndroidManifest` 去掉已废弃的 `package` 属性（由 `namespace` 提供）。

## 非目标（本轮不做）

- 相机硬件控制：点按对焦、手电筒、变焦、切换摄像头、分辨率选择。
- 多语言 UI（中文资源）。
- 发送端页面与 libcimbar 内部逻辑（subtree 不动）。

## Constraints

- 本地不编译：CI 是唯一验证途径，功能写全后一次性 push。
- 只改 app 层（Java / 资源 / JNI 桥 / 构建脚本），不改 `app/src/cpp/libcimbar/`。
- 不破坏已有发送端流程（`WebViewActivity` 仍加载 `assets/index.html#ww=1`）。
